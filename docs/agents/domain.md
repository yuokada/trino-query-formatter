# Domain docs

This repository uses a single-context domain documentation layout.

Before starting work, read the following files when they exist:

- `CONTEXT.md` at the repository root
- Relevant ADRs under `docs/adr/`

If these files do not exist, continue without raising an error. Create them through `domain-modeling` only when durable terminology or an important architectural decision has been resolved.

Use the vocabulary defined in `CONTEXT.md` consistently and explicitly flag proposals that conflict with an existing ADR. Do not store implementation plans, temporary task details, or complete interview transcripts in `CONTEXT.md`.
